# 보험 청구 심사 지원 대시보드

`보험청구_관리자_대시보드.html`을 브라우저로 열면 바로 실행됩니다. 이 한 파일에 화면, 계산 엔진, 모델 파라미터, 예시 입력이 모두 들어 있어 인터넷·서버·설치가 필요 없습니다.

왼쪽에 사고·보험·청구 정보를 입력하면 오른쪽에 모델 점수(0~100), 검토 구분(일반 검토 / 추가 확인 권고), 점수에 영향을 준 정보, 미상 입력 처리 내역과 경고가 표시되고, 담당자 판단과 검토 메모를 남길 수 있습니다.

## 시연 순서

1. 처음 열면 DEMO-001이 분석되어 있습니다. 점수 57.9점, 추가 확인 권고.
2. `피해 정도`를 `큰 손상`에서 `경미한 손상`으로 바꿉니다. 결과가 흐려지고 "입력이 바뀌었습니다"가 표시됩니다. `다시 분석하기`를 누르면 약 9.1점으로 바뀝니다.
3. DEMO-003을 고르고 검토 기준을 10점에서 20점으로 바꿉니다. 점수 11.8점과 영향 요인은 그대로이고 검토 구분만 바뀝니다.
4. DEMO-002에서 미상 3개가 어떻게 처리됐는지 `미상 입력 처리와 경고`에서 확인합니다.
5. 필수 항목을 하나 비우고 분석해 봅니다. 오류가 표시되고 분석·기록·저장이 막힙니다.
6. 담당자 판단과 메모를 기록하고 `결과 JSON 저장`을 누릅니다.

`빈 양식으로 직접 입력`을 누르면 예시 없이 새 청구를 입력할 수 있습니다.

## 세 화면

- **청구 분석** 입력 24개 → 모델 계산 → 점수 / 검토 구분 → 영향 요인 → 미상 처리·경고 → 담당자 검토.
- **모델 평가** 패키지에 들어 있는 교차검증 자료를 범위별로 나누어 표시합니다. 범위 A는 평가 폴드 1개의 200건, 범위 B는 교차검증 첫 반복의 1,000건(기준 점수별 집계), 범위 C는 평가 15회의 평균입니다.
- **연결 데이터** 패키지 구성, 화면 영역과 값의 출처, 현재 입력, 저장될 JSON 미리보기, 계산 자체 점검, 입력 항목 정의.

## 2026-11-12에 바뀐 점

화면

- 화면 구조와 스타일을 새로 정리했습니다. 글자 크기(최소 12px)·여백·대비를 통일했고, PC는 입력과 결과를 나란히, 좁은 화면은 세로로 배치합니다.
- 점수는 큰 숫자와 0~100 막대로, 검토 기준은 막대 위의 표시선과 `10점 이상 / 20점 이상` 버튼으로 보여 줍니다. 기본값은 10점입니다.
- 필수 항목에 `필수` 표시, 단위, 입력 가능 범위를 붙였습니다. 개발용 필드명은 `개발용 필드명 표시`를 켰을 때만 보입니다. 24개 항목 전체와 계산 과정은 펼쳐서 봅니다.
- 영향 요인의 숫자는 로그오즈 기여임을 화면에 적었습니다.
- 모델 평가 화면에 평가 폴드 1개의 누적 그래프를 추가하고, 수치마다 계산 범위를 표시했습니다. 그래프와 표는 `evaluation.rows`의 사기 표시와 순위를 그대로 누적한 것입니다.

동작

- 화면 상태를 네 가지로 나눴습니다. 최신 결과 / 재분석 필요(이전 결과를 흐리게 표시) / 분석 차단(이전 결과를 숨김) / 결과 없음. 최신 결과가 아닐 때는 검토 기록과 JSON 저장이 막힙니다.
- 입력을 분석했던 값으로 되돌리면 재분석 없이 최신 상태로 돌아옵니다. 같은 입력이면 결과가 같기 때문입니다.
- 오류는 고치기 시작한 항목만 지워집니다. 오류 요약에서 항목을 누르면 그 입력으로 이동합니다.
- 다시 분석하거나 기준을 바꿔도 작성 중인 메모는 지우지 않습니다. 다시 분석하면 담당자 판단 선택만 초기화됩니다. 다른 예시로 옮기거나 초기화하면 메모도 지워집니다.
- 빈 양식 직접 입력을 추가했습니다. 식별자는 `USER-001`부터 붙습니다.
- 선택 항목인 범주(충돌 방향, 재물 피해 여부, 경찰 보고서 확보)의 빈 상태는 `미상 (모름)`입니다.
- 저장 JSON의 `context`에 `input_source`, `inputs_match_sample`, `modified_fields`를 추가했습니다. 예시를 고쳐서 분석했는지 알 수 있습니다. 기존 키와 값은 그대로이며 `data/sample_result.json`과 호환됩니다. 직접 입력한 청구는 `source_row`와 `sample_was_in_training_data`가 `null`입니다.
- 범례·막대처럼 여러 요소를 한 번에 넣는 곳은 공통 함수(`setChildren`)로 처리합니다. 화면의 모든 글자는 `textContent`로 넣습니다.

바꾸지 않은 것

- `src/engine.js`와 `data/` 아래 파일 4개는 받은 그대로입니다(SHA-256 일치). 모델 계수, 전처리 값, 설명 기준값, 입력 24개의 의미와 범주, 필수 여부, 검증 규칙을 바꾸지 않았습니다.
- 계산은 `analyzeCase(inputs)`, 검토 구분은 `decision(score, threshold)`만 사용합니다.

## 소스를 고친 뒤

```
python3 rebuild_from_payload.py           # HTML 다시 만들기 (Windows는 python)
python3 rebuild_from_payload.py --check   # 소스와 HTML이 일치하는지만 확인
node validation/run_engine_checks.mjs     # 엔진·패키지 검사
node validation/run_browser_checks.mjs    # 화면 동작 검사 (Chrome 또는 Edge, Node.js 22 이상)
```

HTML은 직접 고치지 말고 `src/`를 고친 뒤 다시 만듭니다. 브라우저 콘솔에서는 `ClaimDashboard.state`, `ClaimDashboard.makeExport()`로 상태와 저장 내용을 볼 수 있습니다.

## 계산과 표현

- 전체 1,000건으로 학습한 로지스틱 회귀의 계수를 사용합니다. 이 패키지에는 계산 파라미터, 입력 예시 5건, 평가 자료만 들어 있고 원본 학습 자료 1,000건은 들어 있지 않습니다.
- 숫자 빈칸은 학습 중앙값으로 채운 뒤 학습 평균과 표준편차로 변환합니다. 범주는 학습 범주별 계수를 적용하고, 미상은 미상 범주로 계산합니다.
- 숫자 0, 미상(`null`), 문자열 `"None"`(연락한 기관 없음)은 서로 다른 값입니다.
- 필수 12개 항목은 비우면 분석을 막습니다. 음수 청구액, 잘못된 시각, 목록에 없는 범주도 막습니다. 허용 범위 안이지만 학습 자료 범위 밖인 값은 계산하고 경고를 표시합니다. 시연용 입력 정책이며 최적 정책으로 검증하지 않았습니다.
- 영향값은 각 입력의 계산 기여에서 학습 자료의 평균 기여를 뺀 로그오즈 값입니다. 점수에 더하는 배점이 아닙니다.
- 모델 점수는 실제 보험사에서 검증된 사기 확률이 아닙니다. 추가 검토를 돕는 참고 정보입니다. 10점·20점 기준도 최적값으로 검증하지 않았습니다.
- 금액은 원본 데이터의 단위이며 원화로 환산하지 않았습니다.
- 담당자 판단과 메모는 모델 점수를 바꾸지 않고, 이 탭의 메모리에만 있다가 새로고침하면 사라집니다.

## 검증

2026-11-12에 이 버전으로 직접 실행한 검사입니다. 결과는 `validation/rerun_engine_checks.json`과 `validation/rerun_browser_checks.json`에 있습니다.

- **엔진·패키지 17개 통과** (Node.js). 예시 5건이 `expected_score`와 일치(최대 오차 약 5e-15), DEMO-001 57.898465222점, 피해 정도를 Minor Damage로 바꾸면 9.059383729점, DEMO-003 11.758962783점과 기준별 검토 구분, 필수 12개 항목 차단, 0·미상·"None" 구분, 잘못된 값 14종 차단, 학습 범위 밖 경고, 설명값 합산, 엔진·데이터 해시 일치, HTML과 소스 일치, 외부 자원 없음.
- **화면 동작 56개 통과** (Chrome 158, PC 1440×900과 모바일 390×844 에뮬레이션에서 각 28개). 위 점수 확인, 입력 수정 후 저장·내보내기 차단, 분석 실패 시 이전 결과 숨김, 메모 기록 후 점수 불변, 메모의 HTML이 글자로만 표시됨, 내려받은 JSON 파일 내용, 세 화면 이동과 예시 전환, 빈 양식 입력, 초기화, 새로고침 후 기록 삭제, 가로 스크롤 없음, 외부 요청과 페이지 오류 없음.

실행하지 못한 검사

- Python 모델과의 1,000건 예측 대조. 원본 자료와 Python 모델이 패키지에 없습니다. `validation/engine_checks.json`이 기존 기록이고, 엔진과 데이터가 그때와 바이트 단위로 같습니다.
- Safari·Firefox, 실제 휴대전화 기기, 화면 낭독기.

이 검사들은 계산과 화면 동작이 의도대로인지 확인한 것입니다. 모델 성능을 새로 검증한 것이 아닙니다.

## 제한 사항

- 단건 분석만 지원합니다. CSV 업로드, 여러 건 비교, 로그인, 서버 저장, 외부 연동은 없습니다.
- 예시 5건은 학습에 사용된 행이므로 그 점수로 성능을 판단할 수 없습니다.
- 모델 평가 화면의 "5분할 × 3회"는 팀이 제공한 평가 설명에 따른 문구입니다. payload에는 이 값이 직접 들어 있지 않습니다. 평균값에 15를 곱하면 모두 정수가 되는 것만 확인했습니다.
- `손상 정도만 쓰는 모델`은 점수가 4가지뿐이라 동점이 많습니다. 누적 그래프는 평가 자료에 기록된 순위를 그대로 따릅니다.
